## 1. Objective

Разработать, внедрить и верифицировать полный интерактивный учебный модуль Недели 2 («Принципы SOLID и Dependency Injection») на сквозном кейсе транспортной системы Алматы (`Avtobys`):
1. Создать структурированный методический контент Недели 2 в каталоге `content/week2/`: полный текст лекции по 5 принципам SOLID и DI со схемами Mermaid.js, интерактивный квиз на 6–8 вопросов (10 баллов), условия практической лабораторной работы по рефакторингу `MonolithicAvtobysService` с эталонным сьютом автотестов `test_solid_w2.py` на `pytest` (15 баллов).
2. Реализовать сервисный слой (`app/services/week2_content_service.py`) и бэкенд API (`app/api/week2.py`) для выдачи теории, проверки квиза и запуска автопроверки практики через песочницу `RunnerService` с сохранением попыток в `Submission` и баллов в `TopicProgress` (SQLite).
3. Создать интерактивный Zero-build интерфейс в `frontend/`: динамический экран Недели 2 с вкладками «📖 1. Лекция SOLID & DI», «❓ 2. Квиз», «💻 3. Практикум» со встроенным редактором кода, запуском проверки и отображением консольного вывода `pytest`.
4. Обновить `app/api/course.py` с актуальной тематикой Недели 2 (`is_ready: True`).
5. Обеспечить 100% покрытие тестами (`tests/test_api_week2.py`, `tests/test_content_week2.py`), отсутствие регрессий платформы и Недели 1, чистоту линтера `ruff`.

## 6. Technical Guidance

- **Паттерн «копия W1»:** Использовать `app/services/content_service.py` и `app/api/week1.py` как образец. Создать изолированный `week2_content_service.py` с `CONTENT_DIR = Path("content") / "week2"`.
- **Монолит для рефакторинга:** Стартовый `MonolithicAvtobysService` должен совмещать 3–4 ответственности: расчёт тарифа (с if-elif по типу пассажира), валидацию проезда, логирование транзакций и запись в условную БД. Нарушения SRP и OCP должны быть наглядными и документированными в комментариях.
- **Тестовый сьют `test_solid_w2.py`:** Проверять контракты через `isinstance(obj, ABC)`, наличие абстрактных методов, инъекцию через конструктор, а не конкретные имена классов. Проверить OCP: добавление нового тарифа без модификации существующих классов.
- **Балльная схема практики:** 15 баллов за 100% pass всех тестов; 0 баллов при любом failure. Промежуточные баллы не начисляются.
- **Фронтенд Week 2:** Выделить логику Недели 2 в `frontend/js/week2.js` с экспортом функции `loadWeek2Module()`. Добавить в `app.js` навигацию и `showView("week2")`.
- **Mermaid-диаграммы:** Использовать `classDiagram` для визуализации декомпозиции: «до» (один MonolithicService) и «после» (абстракция + конкретные реализации + DI).

## 7. Definition of Failure

- ❌ Заглушки `TODO`, `pass`, плейсхолдеры в `content/week2/`.
- ❌ Монолит < 30 строк (слишком простой) или > 100 строк (не уложится в 1 час).
- ❌ Тесты проверяют имена классов вместо контрактов (`isinstance`, `ABC`).
- ❌ Ошибки сохранения баллов в SQLite `TopicProgress` / `Submission`.
- ❌ Добавление Node.js / npm зависимостей.
- ❌ Падение существующих тестов (платформа + Неделя 1).

## 8. Phase Risks & Mitigation

| Риск | Стратегия смягчения |
|---|---|
| Монолит слишком сложен для 1 часа | Ограничить 50–80 строк с 3–4 явными нарушениями; добавить комментарии-подсказки |
| Студент не понимает, что рефакторить | Стартовый шаблон содержит пустые абстрактные классы и docstrings с инструкциями |
| Хрупкие тесты SOLID при вариативности решений | Проверять контракты (ABC, DI-инъекция), а не имена; тесты через isinstance |
| Конфликт CSS/JS с Неделей 1 | Изолированные ID (`w2-*`), отдельный `week2.js` |
| Зависание кода студента | Таймаут RunnerService 5 секунд |
