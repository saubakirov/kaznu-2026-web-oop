## 1. Objective

Разработать, внедрить и верифицировать базовый технический контур платформы Web OOP:
1. Бэкенд на FastAPI с точкой входа, эндпоинтами проверки состояния (`/api/health`) и обзора курса (`/api/course/overview`).
2. Персистентность на SQLite через SQLAlchemy 2.0 с автоматической инициализацией таблиц при старте.
3. Zero-build фронтенд в `frontend/` (HTML5, Tailwind CSS через CDN, Vanilla JS ES-модули, рендеринг Mermaid.js), монтируемый статикой FastAPI на корневом URL `/`.
4. Сервис безопасного выполнения тестов `RunnerService` с синтаксической AST-валидацией и таймаутом subprocess pytest 5 секунд.
5. Интеграционное тестовое покрытие (`pytest`) и соответствие линтеру `ruff`.

## 2. Scope

### In Scope

- Добавление зависимости `sqlalchemy>=2.0.0` в `pyproject.toml`.
- Создание пакета `app/` со структурой:
  - `app/main.py`: сборка FastAPI приложения, подключение роутеров, lifespan-инициализация БД, раздача статики `StaticFiles(directory="frontend", html=True)`.
  - `app/core/config.py`: настройки (`Settings`) базы данных, путей и параметров выполнения раннера.
  - `app/db/session.py`: `create_engine`, фабрика `sessionmaker`, `Base`, функция `init_db()`.
  - `app/models/course.py`: декларативные модели `Student`, `TopicProgress`, `Submission`.
  - `app/api/health.py`: эндпоинт `GET /api/health` со статусом API, версией и проверкой доступности SQLite.
  - `app/api/course.py`: эндпоинт `GET /api/course/overview` со структурой недель.
  - `app/api/runner.py`: эндпоинт `POST /api/runner/check` для тестовой проверки передачи кода в песочницу.
  - `app/services/runner.py`: валидация AST и изолированное выполнение `pytest` через `subprocess.run(timeout=5)`.
- Создание фронтенда `frontend/`:
  - `frontend/index.html`: адаптивная верстка со строкой статуса сервиса, каркасом недель курса и блоком UML-диаграммы.
  - `frontend/js/api.js`: модуль запросов к бэкенду.
  - `frontend/js/app.js`: инициализация UI, опрос статуса, рендеринг диаграммы Mermaid.js.
  - `frontend/css/styles.css`: минимальные вспомогательные стили.
- Создание тестов в `tests/`:
  - `tests/test_api_health.py`: проверка `GET /api/health` и `GET /api/course/overview` через `TestClient`.
  - `tests/test_db_models.py`: проверка создания и выборки записей из SQLite моделей.
  - `tests/test_runner_service.py`: проверка успешного выполнения кода, перехвата синтаксических ошибок и таймаута при зависании.
- Создание обязательного файла свидетельств `evidence/EV__OOP_20261009-123309_PFBZ.md`.

## 5. Acceptance Criteria

### AC-1: Бэкенд и эндпоинты состояния (API Health & Overview)

FastAPI приложение запускается, роуты `/api/health` и `/api/course/overview` отдают корректный JSON со статусами.
- [ ] Запрос `GET /api/health` возвращает статус `200 OK`, `status: "ok"`, подтверждает подключение к базе данных (`database: "connected"`).
- [ ] Запрос `GET /api/course/overview` возвращает базовую структуру недель курса (3 недели с темами и статусом готовности).
- [ ] Автоматическая документация Swagger доступна по адресу `/docs`.

**Gate:** `pytest tests/test_api_health.py -v`  
**Evidence:** HTTP ответ `GET /api/health` с кодом 200 и валидным телом в реальном запуске uvicorn.

### AC-2: Слой хранения данных (SQLite & SQLAlchemy 2.0)

Настроен слой персистентности SQLite с моделями для студентов и прогресса.
- [ ] Файл БД `data/web_oop.db` создается автоматически при инициализации приложения.
- [ ] Модели `Student`, `TopicProgress`, `Submission` объявлены через SQLAlchemy 2.0 декларативный стиль (`Mapped`, `mapped_column`).
- [ ] Корректно выполняются операции создания и чтения записей (создание студента, фиксация прогресса темы).

**Gate:** `pytest tests/test_db_models.py -v`  
**Evidence:** Проверка создания файла `data/web_oop.db` и успешное сохранение/чтение записей в сессии.

### AC-3: Zero-Build фронтенд и статическая раздача

Фронтенд отдается сервером FastAPI на корневом URL `/` и полноценно отображает интерфейс в браузере.
- [ ] Сервер монтирует каталог `frontend/` через `StaticFiles` на `/`.
- [ ] Файл `frontend/index.html` использует стили Tailwind CSS через официальный CDN.
- [ ] На странице отображаются динамические индикаторы здоровья бэкенда и БД (зеленый статус при успешном ответе API).
- [ ] Подключена библиотека Mermaid.js (через CDN), рендерится тестовая UML-диаграмма класса `Passenger` предметной области `Avtobys`.
- [ ] В проекте отсутствуют `node_modules`, `package.json`, сборщики webpack/vite.

**Gate:** `pytest tests/test_api_health.py -k test_static_root -v`  
**Evidence:** Открытие `http://localhost:8000` в браузере, проверка наличия элементов UI и отсутствия ошибок в консоли.

### AC-4: Изолированный раннер кода (RunnerService)

Сервис `RunnerService` надежно и безопасно исполняет код через `pytest` в изолированном процессе.
- [ ] Метод проверки валидирует синтаксис входного кода через `ast.parse`.
- [ ] При наличии синтаксической ошибки немедленно возвращается информативный статус ошибки без падения.
- [ ] Код и проверочный тест записываются во временную директорию (`tempfile`) и запускаются через `subprocess.run([sys.executable, "-m", "pytest", ...], timeout=5)`.
- [ ] Скрипт с бесконечным циклом прерывается по истечении 5 секунд с возвратом статуса `timeout`.
- [ ] Эндпоинт `POST /api/runner/check` принимает код и тест, возвращает структурированный вердикт (`passed: bool`, `output: str`).

**Gate:** `pytest tests/test_runner_service.py -v`  
**Evidence:** Прохождение теста с преднамеренным бесконечным циклом и теста с успешным сложением двух чисел.

### AC-5: Сквозное качество кода и локальный запуск

Кодовая база чиста, типизирована, проверена статическим анализом и готова к работе.
- [ ] Все тесты в каталоге `tests/` проходят успешно (`pytest`).
- [ ] Линтер `ruff check .` завершается с нулевым кодом возврата (0 ошибок, 0 предупреждений).
- [ ] Сервер стартует командой `python -m uvicorn app.main:app --port 8000`.

**Gate:** `pytest && ruff check .`  
**Evidence:** Вывод команд pytest и ruff с нулевым кодом возврата.

## 6. Technical Guidance

- Использовать Python 3.12+ современные аннотации типов (`str | None`, `list[str]`).
- В `app/services/runner.py` для вызова процесса использовать `sys.executable`, чтобы гарантировать запуск того же интерпретатора Python, где установлен pytest.
- Временные файлы тестов создавать через `tempfile.TemporaryDirectory()`, чтобы автоматически удалять мусор после проверки.
- Во фронтенде использовать нативные ES-модули (`<script type="module" src="js/app.js">`) для модульности кода без сборщика.
- Для SQLite базы предусмотреть создание каталога `data/` при старте, если он отсутствует.

## 7. Definition of Failure

- ❌ Запуск фронтенда требует `npm install` или наличие Node.js в системе.
- ❌ Падение или зависание сервера при выполнении некорректного или бесконечного студенческого кода.
- ❌ Невозможность старта приложения из-за жесткой привязки к внешним сетевым портам или сервисам.
- ❌ Ошибки линтера `ruff check .` или провал тестов `pytest`.
